# 支付与对账设计

[多支付渠道 Mock 支付与对账设计开发方案](multi_channel_mock_payment_reconciliation_design.md)

方案基于当前仓库源码和截至 2026-10-16 查阅的官方支付资料，设计银行卡／银联、微信、支付宝和数字人民币四种 Mock 支付方式。

核心决策：

- 使用支付策略 + Spring 注册工厂，统一处理支付编排、幂等和对账。
- 保留订单级支付聚合，新增支付尝试和独立 Mock 渠道账。
- 区分实时交易核对、次日日终账单、渠道资金到账和平台卖家结算。
- 银联默认模拟 T+1 工作日到账，微信／支付宝默认模拟 D+1 自然日到账；数字人民币默认模拟 D+0 钱包到账。这些到账规则是项目选定的 Mock 协议。
- 四渠道均有日终账单复核；数字人民币的 D+0 增量核对不代替完整日账。

详细文档包含数据模型、状态机、接口、前端、退款与账本改造、任务调度、差异闭环、故障注入、迁移计划和验收用例。目前仅为设计，未修改支付实现或执行数据库迁移。
